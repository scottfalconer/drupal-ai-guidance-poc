# Testing AI Guidance

This module should be tested as a deterministic Drupal module first. Model-backed
evaluation runs are useful product evidence, but they are not the release gate.
Normal automated tests must not require OpenAI or other model-provider credits.

## Local hygiene

From the module repository:

```bash
git status --short
find . \
  -path './vendor' -prune -o \
  -path './web' -prune -o \
  -path './docroot' -prune -o \
  -name '*.php' -print0 | xargs -0 -n1 php -l
```

The candidate patch should not contain `.demo-logs/`, `.demo-recordings/`,
browser captures, local cache files, or generated demo artifacts.

## DDEV Drupal site

For the current proof of concept, validate both shapes when practical:

```text
web/modules/contrib/ai_guidance
web/modules/contrib/ai/modules/ai_guidance
```

The first path is the standalone contrib-module layout. The second path is the
in-tree development layout when iterating beside `drupal/ai`.

Run syntax lint inside the Drupal container so the PHP version matches Drupal:

```bash
AI_GUIDANCE_DIR=web/modules/contrib/ai_guidance
ddev exec "find $AI_GUIDANCE_DIR -name '*.php' -print0 | xargs -0 -n1 php -l"
```

Clear caches after service or plugin changes:

```bash
ddev drush cr
```

## Clean Drupal CMS smoke

Use a fresh Drupal CMS project when checking install instructions. If using
DDEV, use a DDEV version that satisfies the constraint generated by the current
Drupal CMS project template.

```bash
mkdir -p ~/dev/ai-guidance-clean-cms-test
cd ~/dev/ai-guidance-clean-cms-test
ddev config --project-type=drupal11 --docroot=web --create-docroot --project-name=ai-guidance-clean-cms-test
ddev start
ddev composer create-project drupal/cms -y
ddev restart
ddev drush site:install minimal -y --account-name=admin --account-pass=admin --site-name='AI Guidance Clean CMS'
ddev drush recipe /var/www/html/recipes/drupal_cms_starter -y
ddev drush recipe /var/www/html/recipes/drupal_cms_ai -y
```

Install the local POC as standalone contrib code:

```bash
mkdir -p web/modules/contrib/ai_guidance
rsync -a \
  --exclude='.git' \
  --exclude='.ddev' \
  --exclude='vendor' \
  --exclude='web' \
  --exclude='docroot' \
  --exclude='node_modules' \
  --exclude='test_outputs' \
  /path/to/drupal-ai-guidance-poc/ \
  web/modules/contrib/ai_guidance/
```

Enable the base and demo modules:

```bash
ddev drush pm:enable ai_guidance -y
ddev drush cr
ddev drush pm:enable ai_guidance_best_practices ai_guidance_cms_demo -y
ddev drush ai-guidance:setup-demo
```

Apply the temporary AI Assistant API patch for context-only assistant support:

```bash
cd web/modules/contrib/ai
patch -p1 < /path/to/drupal-ai-guidance-poc/patches/ai-assistant-api-context-actions.patch
cd -
ddev drush cr
```

Verify the clean CMS install:

```bash
ddev drush core:requirements | grep -A3 -B1 'AI Guidance'
ddev drush ev '$defs = \Drupal::service("ai_assistant_api.action_plugin.manager")->getDefinitions(); foreach (["ai_guidance_site_state_context", "ai_guidance_site_config_context", "ai_guidance_help_context"] as $id) { echo $id . ": " . (isset($defs[$id]) ? "yes" : "no") . PHP_EOL; }'
ddev drush ev '$assistant = \Drupal::entityTypeManager()->getStorage("ai_assistant")->load("drupal_guidance_assistant"); $contexts = \Drupal::service("ai_assistant_api.action_plugin.manager")->listAllContexts($assistant, "clean-cms-smoke", $assistant->get("actions_enabled") ?: []); echo "contexts=" . count($contexts) . PHP_EOL; foreach ($contexts as $context) { echo ($context["title"] ?? "untitled") . PHP_EOL; }'
ddev drush ai-guidance:reset-lesson-1
ddev drush ai-guidance:setup-lesson-2
```

On clean Drupal CMS without Context Control Center, `ai-guidance:setup-lesson-2`
should exit successfully with a warning that CCC policy context was not created.

## PHPUnit

If the Drupal install does not already include PHPUnit tooling, install dev
tools in the Drupal project, not in a production site. Match `drupal/core-dev`
to the installed Drupal core constraint or exact version:

```bash
ddev composer config --no-plugins allow-plugins.dealerdirect/phpcodesniffer-composer-installer true
ddev composer config --no-plugins allow-plugins.phpstan/extension-installer true
ddev composer require --dev drupal/core-dev drupal/coder phpstan/phpstan mglaman/phpstan-drupal --with-all-dependencies
```

Run unit tests:

```bash
AI_GUIDANCE_DIR=web/modules/contrib/ai_guidance
ddev exec "SIMPLETEST_BASE_URL=http://ai-guidance-clean-cms-test.ddev.site SIMPLETEST_DB=mysql://db:db@db/db BROWSERTEST_OUTPUT_DIRECTORY=/tmp vendor/bin/phpunit -c web/core/phpunit.xml.dist $AI_GUIDANCE_DIR/tests/src/Unit"
```

Run kernel tests:

```bash
AI_GUIDANCE_DIR=web/modules/contrib/ai_guidance
ddev exec "SIMPLETEST_BASE_URL=http://ai-guidance-clean-cms-test.ddev.site SIMPLETEST_DB=mysql://db:db@db/db BROWSERTEST_OUTPUT_DIRECTORY=/tmp vendor/bin/phpunit -c web/core/phpunit.xml.dist $AI_GUIDANCE_DIR/tests/src/Kernel"
```

## Coding standards

Run PHPCS from the Drupal project after installing `drupal/coder`:

```bash
AI_GUIDANCE_DIR=web/modules/contrib/ai_guidance
ddev exec "vendor/bin/phpcs --standard=$AI_GUIDANCE_DIR/phpcs.xml.dist $AI_GUIDANCE_DIR"
```

PHPStan is optional until the Drupal project has a stable PHPStan Drupal setup.
This lightweight command is useful for catching dependency-injection and obvious
type issues without treating PHPStan as the only gate:

```bash
AI_GUIDANCE_DIR=web/modules/contrib/ai_guidance
ddev exec "vendor/bin/phpstan analyse $AI_GUIDANCE_DIR/src $AI_GUIDANCE_DIR/modules/ai_guidance_ai_context/src $AI_GUIDANCE_DIR/modules/ai_guidance_best_practices/src $AI_GUIDANCE_DIR/modules/ai_guidance_cms_demo/src --autoload-file=web/core/includes/bootstrap.inc --level=1 --memory-limit=1G"
```

Record the exact command and result in the review packet.

## Optional-module matrix

The base module must install and compile without optional bridges. Then test the
following combinations when the dependencies are available:

- `ai_guidance` only.
- `ai_guidance` plus `ai_guidance_best_practices`.
- `ai_guidance` plus `ai_guidance_ai_context` when `ai_context` is installed.
- Optional evidence modules present and absent: ECA, Webform, Search API.
- `ai_guidance_cms_demo` enabled only for demo environments.

Useful smoke commands:

```bash
ddev drush pm:enable ai_guidance -y
ddev drush cr
ddev drush pm:enable ai_guidance_best_practices -y
ddev drush cr
ddev drush pm:enable ai_guidance_cms_demo -y
ddev drush ai-guidance:setup-demo
```

## Manual smoke

Use Chrome MCP or another real browser for final demo smoke:

- Debug page denies normal users and allows `administer ai guidance`.
- Demo page refreshes the assistant.
- Lesson 1: create one draft Article, evaluate the result, explain the role
  boundary, and avoid generic promoted-front-page advice when site evidence says
  otherwise.
- Lesson 2: Context Control Center policy context guides draft suggestions but
  does not grant publish/provider/permission authority.

## Evaluation matrix

Re-run the same-model evaluation matrix after cleanup, using the same model for
stock and guidance variants. Treat it as value evidence. Do not use it as a
substitute for unit, kernel, access, and browser smoke tests.
