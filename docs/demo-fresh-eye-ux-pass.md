# Demo Fresh-Eye UX Pass

## Questions From The Pass

1. Would a viewer understand where the `Sources` section comes from?
   - Resolution: Sources now distinguish linked Help/Drupal.org references from live Drupal evidence gathered from the current request and installed site.

2. Does `What can I do on this page?` teach the next safe action, or does it inventory the form?
   - Resolution: Current-form evidence is compact. Advanced/admin controls are filtered, form-display component lists are not exposed, and the model is told to mention the required field plus only a few user-facing controls.

3. Does the first Article-form answer fit in the expanded chat window?
   - Resolution: The live smoke answer is now a compact create-Article response with Title, Deck, Body, Topics, Save, and Preview, followed by role boundaries and short Sources.

4. Does Lesson 2 make clear that policy context is not authorization?
   - Resolution: The Lesson 2 response states that Context Control Center guides suggestions, while Drupal permissions, workflow, and editorial review remain authoritative.

5. Does the front-page question avoid generic Drupal advice?
   - Resolution: The live smoke answer explains that the current front page is a Canvas page/homepage surface, not a generic Article listing, and separates editor verification from site-builder front-page changes.

## Viewer-Facing Source Pattern

- Live evidence labels: `[A1]`, `[R1]`, `[E1]`, `[F1]`, `[W1]`, `[L1]`, `[M1]`.
- Linked reference labels: Help Topics, route Help, Context Control Center policy context, package guidance, and Drupal.org documentation when a safe URL is available.
- Do not invent external URLs for live evidence. It is evidence from the current request and installed site.
